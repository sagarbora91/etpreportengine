### The H-1 claim and the strengthened trigger

**Codex is right that the audit's H-1 finding was wrong.** Migration `0011_phase2_operations.sql:162-164` already contained a last-Owner check inside `trg_application_users_history`, throwing 51100 "At least one active Owner is required." Audit 05 looked at migration `0013` and concluded no trigger existed. H-1 as written should be struck.

**The strengthened trigger is sound on the four behaviours asked about, and wrong in one respect that was not asked about.**

- *UPDLOCK/HOLDLOCK* — correct. The existence check now runs as `SELECT ... FROM dbo.application_users WITH(UPDLOCK,HOLDLOCK) WHERE role_code='OWNER' AND is_active=1`, which serialises two concurrent transactions each demoting a different Owner. Under the old `0011` check both could have seen the other's Owner still active and committed, leaving zero Owners. The second transaction now blocks until the first commits and then throws.
- *Multi-row updates* — correct, and verified: a single `UPDATE` demoting every Owner at once was refused. The check tests the resulting table state rather than per-row values, so batch size is irrelevant.
- *Deletes* — correct, and verified.
- *Deactivation* — correct, and verified.
- *Regression* — the `0011` trigger ended with an `INSERT dbo.operational_audit(event_type, outcome, safe_detail, application_version, actor_name) VALUES('UserAdministration','Succeeded',…, ORIGINAL_LOGIN())`. The `0016` replacement omits it. Measured on the copy: two successful user changes (one insert, one demotion) produced 3 `application_user_history` rows and **zero** new `UserAdministration` rows in `operational_audit` (count 1 before, 1 after). `OBJECT_DEFINITION` of the deployed trigger confirms it no longer references `operational_audit`. Nothing in `src/` writes a `UserAdministration` audit row either — the string appears only in the allow-list at `OperationalAuditRepository.cs:14` — so after `0016` no user-administration change is recorded in the operational audit trail at all, whether made in the app or directly in SSMS. Item R1.
